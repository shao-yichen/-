## 二、Contract Register 模块

### US-001 · 切换 Contract Ledger 视图

**作为** 市场营销人员、项目管理人员或其他获授访问权限的人员  
**我想要** 在默认列表和合同管理台账之间切换  
**以便于** 以适合当前任务的字段查看合同

**验收标准**

- [ ] 正常场景。点击 Contract Ledger 切换至台账，再次点击返回默认视图，筛选区与列随视图切换。
- [ ] 异常场景。授权范围内无匹配记录时，显示空列表，仍可切换视图。
- [ ] 边界条件。切换前已有条件、排序和分页时，切换后清空条件、回到第 1 页并按 Created time 倒序。

**业务规则**

- **操作规则**：点击 Contract Ledger 切换至台账，再次点击返回默认视图，筛选区与列随视图切换。
- **数据规则**：两视图读取同一授权范围的合同主数据，按 Contract No. 去重。No. 按完整结果连续编号。
- **校验规则**：查询限定在用户当前授权范围内，并按系统生成的 Contract No. 去重。
- **状态逻辑**：切换前已有条件、排序和分页时，切换后清空条件、回到第 1 页并按 Created time 倒序。
- **异常场景**：
  - 授权范围内无记录 / 显示空列表 / 不阻断 / 无

**数据流与依赖**

- **上下游模块/系统**：读取授权合同及台账字段，返回当前视图。
- **第三方对接**：无。
- **定时任务**：无。
- **数据同步**：无。
- **公用数据/表**：合同主数据、货盘与有效汇率。
- **连带影响**：重置查询条件、分页和排序。
- **权限与数据范围**：市场营销人员、项目管理人员及其他获授访问权限的人员均可在授权范围内查询和查看合同。

**前置条件**

- 用户已进入 Contract Register 列表。

**后置条件**

- 目标视图显示按默认条件查询的结果。

**关联 US**：下游 US-002，关联功能 F-CR-001。

**UI 原型**：[Contract Register-原型-v1.0.html](Contract%20Register-原型-v1.0.html)。

### US-002 · 按列检索合同

**作为** 市场营销人员、项目管理人员或其他获授访问权限的人员  
**我想要** 像 Excel 一样从列值列表勾选筛选项  
**以便于** 快速定位符合多个条件的合同

**验收标准**

- [ ] 正常场景。在任一视图打开表头筛选，从组件列出的该列可选值勾选并应用。
- [ ] 异常场景。组合条件没有交集时显示空列表，可继续调整条件。
- [ ] 边界条件。清除条件后恢复其他条件限定的结果。No. 为序号，不提供筛选或排序。

**业务规则**

- **操作规则**：在任一视图打开表头筛选，从组件列出的该列可选值勾选并应用。
- **数据规则**：表头筛选组件列出当前列各行的值，去重后作为可选项。用户可勾选一个或多个值，同一列匹配任一已选值，不同列及筛选区的条件按“且”组合。表头与筛选区中同一字段的筛选条件保持同步。
- **校验规则**：可选项采用该列的展示值。例如`Contract Amount (USD)` 列展示并筛选折算后的美元金额`Counterparty` 列展示并筛选合同相对方名称。
- **状态逻辑**：清除条件后恢复其他条件限定的结果。No. 为序号，不提供筛选或排序。
- **异常场景**：
  - 组合条件无交集 / 显示空列表并保留筛选状态 / 不阻断 / 无

**数据流与依赖**

- **上下游模块/系统**：读取当前视图字段口径和合同记录，返回组合筛选结果。
- **第三方对接**：无。
- **定时任务**：无。
- **数据同步：**无。
- **公用数据/表**：合同主数据、货盘、船舶与用户主数据、有效汇率。
- **连带影响**：刷新当前视图查询结果。
- **权限与数据范围**：市场营销人员、项目管理人员及其他获授访问权限的人员均可在授权范围内查询和查看合同。

**前置条件**

- 用户已进入默认视图或 Contract Ledger 视图。

**后置条件**

- 列表显示匹配记录，筛选区和列头状态一致。

**关联 US**：上游 US-001、US-003、US-004、US-006，关联功能 F-CR-002。

**UI 原型**：[Contract Register-原型-v1.0.html](Contract%20Register-原型-v1.0.html)。

**本次视图字段及取值**

默认列表新增 Contract Attribute 和 Internal / External Charter。默认筛选区新增 Contract Attribute（Spot、Project）、Internal / External Charter（Internal Charter、External Charter）及 Major Contract（Yes、No）。Contract Attribute 取合同最终保存值，Internal / External Charter 根据 Charterer 判定，重大合同按折算后的美元金额判定。

Contract Ledger 为新增视图，展示以下字段。除 No. 外，列筛选通过 Excel 式组件列出对应字段的值供选择。字段显示和筛选均使用下列业务口径。

| 台账字段 | 取值、来源及空值处理 |
|---|---|
| No. | 当前查询结果从 1 连续编号，翻页连续；不支持筛选和排序 |
| PID | 合同关联货盘的 PID；同一 PID 关联的不同合同分别展示 |
| Contract No. | 系统生成的合同编号；列表按该编号去重 |
| Signing Status | 根据合同 Signing date 判定；已明确「已签租约」，完整枚举与其他判定规则待确认 |
| Contract Category | Paradigm contract 为 Yes 时展示 Standard，为 No 时展示 Negotiated，未维护显示 — |
| Our Role | 取 Related Party 中当前用户所属公司的 Type of Related Party，展示 Shipowner 或 Charterer，未找到或未维护显示 — |
| Major Contract (Y/N) | 美元金额大于等于 6,500,000 显示 Y，低于该值显示 N，无法判定显示 — |
| Contract Name / Summary | 合同主数据的 Contract name，未维护显示 — |
| Counterparty | Related Party 中排除当前用户所属公司后的关联方名称，无符合条件的关联方显示 — |
| Performing Vessel | 合同的 Planned performing vessel，未维护显示 —；船舶信息来自船舶主数据 |
| Currency | 合同原始币种代码，如 USD、CNY、EUR，未维护显示 — |
| Contract Amount (USD) | USD 合同取原金额，其他币种按系统生效汇率折算，金额、币种或有效汇率缺失时显示 — |
| Laycan Start Date | 合同 Cargo 中各有效 Laycan 起始日期的最早值，无有效日期显示 — |
| Signed Date | 合同 Signing date，未维护显示 — |
| Execution Status | 已明确「已取消」「已执行」，完整枚举和来源待确认 |
| Spot / Forward | Spot、Forward，来源待确认，未维护显示 — |
| Salesperson | 合同 Business Supervisor，未维护显示 —；用户信息来自用户主数据 |

**待确认字段口径**

- Signing Status 根据 Signing date 判断，已知选项为「已签租约」，完整枚举及其他判定规则待确认。
- Execution Status 已知选项为「已取消」「已执行」，完整枚举及取数来源待确认。
- Spot / Forward 取值为 Spot、Forward，取数来源待确认。此字段与 Contract Attribute 的 Spot、Project 分别维护业务口径。

### US-003 · 筛选 Major Contract

**作为** 市场营销人员、项目管理人员或其他获授访问权限的人员  
**我想要** 从默认视图筛出重大或非重大合同  
**以便于** 按统一金额口径查看合同

**验收标准**

- [ ] 正常场景。在默认筛选区选择 Major Contract 的 Yes 或 No。台账展示 Y、N 或 —。
- [ ] 异常场景。金额、币种或有效汇率缺失时显示 —，不命中 Yes 或 No。
- [ ] 边界条件。折算金额恰好为 6,500,000 USD 时命中 Yes。

**业务规则**

- **操作规则**：在默认筛选区选择 Major Contract 的 Yes 或 No。台账展示 Y、N 或 —。
- **数据规则**：取合同金额和币种。USD 直接使用原金额，其他币种按系统生效汇率折算。折算金额 ≥ 6,500,000 USD 为 Yes，低于该值为 No。
- **校验规则**：比较折算后的美元金额，临界值包含在 Yes 内。
- **状态逻辑**：折算金额恰好为 6,500,000 USD 时命中 Yes。
- **异常场景**：
  - 金额、币种或有效汇率缺失 / 显示 —，排除于 Yes、No 结果 / 不阻断列表查询 / -

**数据流与依赖**

- **上下游模块/系统**：读取原金额、币种及有效汇率，向默认筛选和台账提供计算结果。
- **第三方对接**：无。
- **定时任务**：无。
- **数据同步**：无。
- **公用数据/表**：合同主数据、系统生效汇率。
- **连带影响**：默认视图筛选和台账使用同一判定。
- **权限与数据范围**：市场营销人员、项目管理人员及其他获授访问权限的人员均可在授权范围内查询和查看合同。

**前置条件**

- 用户可查看合同列表。

**后置条件**

- 列表按选中的重大合同条件返回结果。

**关联 US**：下游 US-002，关联功能 F-CR-003。

**UI 原型**：[Contract Register-原型-v1.0.html](Contract%20Register-原型-v1.0.html)。

### US-004 · 维护 Contract Attribute

**作为** 市场营销人员  
**我想要** 在 New Contract 中选择 Spot 或 Project  
**以便于** 记录合同对应的业务属性

**验收标准**

- [ ] 正常场景。选择 Cargo enquiry/Project/COA 后，现货货盘带出 Spot，项目货盘带出 Project，用户可手动修改。
- [ ] 异常场景。提交必填校验时字段为空，阻止当前操作。
- [ ] 边界条件。自动带出后手动更改，重新查看已保存合同及其列表时显示最终保存值。

**业务规则**

- **操作规则**：选择 Cargo enquiry/Project/COA 后，现货货盘带出 Spot，项目货盘带出 Project，用户可手动修改。
- **数据规则**：Contract Attribute 为选择带出或用户选择的必填单选字段。以最终保存值作为默认列表展示和筛选依据。
- **校验规则**：仅接受 Spot 或 Project 两个值，字段不能为空。
- **状态逻辑**：自动带出后手动更改，重新查看已保存合同及其列表时显示最终保存值。
- **异常场景**：
  - 触发必填校验且未选择属性 / 提示补填 / 阻断当前操作 / 无

**数据流与依赖**

- **上下游模块/系统**。读取所选货盘业务类型，保存属性至合同，供默认列表读取。
- **第三方对接**。无。
- **定时任务**。无。
- **数据同步**。无。
- **公用数据/表**。合同主数据、关联货盘。
- **连带影响**。更新默认列表显示和筛选依据。
- **权限与数据范围**。市场营销人员可在现有授权范围内查看和维护合同。

**前置条件**

- 用户拥有新建权限并已打开 New Contract。

**后置条件**

- 保存后列表读取最终属性值。

**关联 US**：下游 US-002、US-005，关联功能 F-CR-004。

**UI 原型**：[Contract Register-原型-v1.0.html](Contract%20Register-原型-v1.0.html)。

### US-005 · 校验测算表附件

**作为** 市场营销人员  
**我想要** 在 Attachment Info 中上传测算表  
**以便于** 在提交审批前备齐测算材料

**验收标准**

- [ ] 正常场景。点击 Upload，选择 Attachment Type 为测算表并上传文件。附件清单显示对应 Document Type。
- [ ] 异常场景。未有有效测算表时阻止提交，切换到 Attachment Info 并提示上传。
- [ ] 边界条件。存在有效测算表时通过本项校验。修改附件类型或删除最后一份测算表后，再次提交时重新判定。

**业务规则**

- **操作规则**：点击 Upload，选择 Attachment Type 为测算表并上传文件。附件清单显示对应 Document Type。
- **数据规则**：每次 Submit for approval 校验当前合同至少有一份有效的测算表附件。
- **校验规则**：以提交时当前有效附件为准，已删除的附件不计入。
- **状态逻辑**：存在有效测算表时通过本项校验。修改附件类型或删除最后一份测算表后，再次提交时重新判定。
- **异常场景**：
  - 无有效测算表 / 显示附件页签并提示上传 / 阻断提交审批 / Please upload the Calculation Sheet before submitting for approval.

**数据流与依赖**

- **上下游模块/系统**。读取附件类型及有效状态，向合同审批提交入口提供校验结果。
- **第三方对接**。无。
- **定时任务**。无。
- **数据同步**。无。
- **公用数据/表**。合同附件、合同审批。
- **连带影响**。通过本项校验后可继续既有审批流程。
- **权限与数据范围**。市场营销人员可在现有授权范围内查看和维护合同。

**前置条件**

- 用户有合同维护及提交权限，已进入合同表单。

**后置条件**

- 满足附件要求时继续提交，不满足时保持待提交。

**关联 US**：上游 US-004，关联功能 F-CR-005。

**UI 原型**：[Contract Register-原型-v1.0.html](Contract%20Register-原型-v1.0.html)。

### US-006 · 标识 Internal Charter

**作为** 市场营销人员、项目管理人员或其他获授访问权限的人员  
**我想要** 查看和筛选内部或外部租约  
**以便于** 识别海特作为承租方的合同

**验收标准**

- [ ] 正常场景。在默认列表查看 Internal / External Charter，可在筛选区选择对应标识。
- [ ] 异常场景。承租方名称未匹配时，按原型规则不命中 Internal Charter 筛选。
- [ ] 边界条件。其他公司名称即使包含相同字样，也不会命中 Internal Charter。

**业务规则**

- **操作规则**：在默认列表查看 Internal / External Charter，可在筛选区选择对应标识。
- **数据规则**：系统读取 Charterer，当其等于「中远海运特种运输股份有限公司」时判定为 Internal Charter，其他承租方为 External Charter。
- **校验规则**：用 Charterer 公司全称匹配，匹配结果作为筛选依据。
- **状态逻辑**：其他公司名称即使包含相同字样，也不会命中 Internal Charter。
- **异常场景**：
  - 承租方名称未匹配 / 按原型判定为 External Charter / 不阻断 / 无

**数据流与依赖**

- **上下游模块/系统**。读取合同的 Charterer，向默认列表及筛选区提供租约标识。
- **第三方对接**。无。
- **定时任务**。无。
- **数据同步**。无。
- **公用数据/表**。合同主数据中的 Charterer。
- **连带影响**。租约标识变动影响默认列表筛选。
- **权限与数据范围**。市场营销人员、项目管理人员及其他获授访问权限的人员均可在授权范围内查询和查看合同。

**前置条件**

- 用户已进入默认视图。

**后置条件**

- 列表展示标识，并支持按标识检索。

**关联 US**：下游 US-002，关联功能 F-CR-006。

**UI 原型**：[Contract Register-原型-v1.0.html](Contract%20Register-原型-v1.0.html)。
