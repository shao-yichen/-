## 二、航次任务变更模块

### US-VTC-001：按工况维护燃油指标

**作为** 已获航次任务变更维护权限的市场营销人员、调度人员或项目管理人员

**我想要** 按油品维护六项燃油指标

**以便于** 明确变更后的航次方案在不同航行工况下采用的燃油消耗假设和价格依据，为后续燃油成本测算提供基础数据

**验收标准：**

- [ ] 燃油表按油品分行，依次显示正常航行-ECA外（吨/天）、正常航行-ECA内（吨/天）、漂航-ECA外（吨/天）、漂航-ECA内（吨/天）、在港（吨/天）、单价；原“在航（吨/天）”由四项工况日耗替代。
- [ ] 输入 0 或 1.234 可作为有效值；负数、非数字及超过三位小数的值不得作为有效录入。
- [ ] 不同油品同一工况的值分别维护，修改一个油品不改变其他油品的值。

**业务规则：**

- **操作规则**：在燃油部分维护各油品数据，按原单据保存流程处理。
- **数据规则**：六项均为用户录入，前五项为相应工况日耗，单价为每吨燃油价格。
- **校验规则**：非负数字，最多三位小数。
- **状态逻辑**：沿用燃油原有维护状态与权限。
- **异常场景**：负数、非数字或超过三位小数 / 不接受非法值 / 阻断非法值录入 / 无。

**数据流与依赖：**

- **上下游模块/系统**：读写当前单据燃油信息；本次不定义油耗金额或效益计算改动。
- **第三方对接**：无新增。
- **定时任务**：无新增。
- **数据同步**：无新增跨系统同步。
- **公用数据/表**：当前航次任务变更单据及其燃油明细。
- **连带影响**：无新增待办、通知或状态流转。
- **权限与数据范围**：市场营销人员、调度人员和项目管理人员沿用系统统一权限，仅可查看已授权单据；有维护权限时方可修改对应指标。

**前置条件：** 存在可维护的油品行。

**后置条件：** 各油品的燃油指标按原单据保存规则维护。

**关联 US：** 无；关联功能 F-VTC-001。

**UI 原型：** 航次任务变更-原型-v1.0.html

### US-VTC-002：维护港口分项天数

**作为** 已获航次任务变更维护权限的市场营销人员、调度人员或项目管理人员

**我想要** 按港口航段记录四项分项天数

**以便于** 将航段时间安排与相应油耗工况对应起来，核对方案中正常航行、漂航及 ECA 内外的时间构成

**验收标准：**

- [ ] “航行天数”右侧依次展示正常航行-ECA外天数、正常航行-ECA内天数、漂航-ECA外天数、漂航-ECA内天数。
- [ ] 在原有可维护条件下，0 和 1.25 可作为有效输入；负数、非数字及超过两位小数的值不得作为有效录入。
- [ ] 在不同港口行录入的分项值相互独立。

**业务规则：**

- **操作规则**：按现有港口维护方式填写四项分项天数。
- **数据规则**：四项均为用户录入，单位为天，按当前港口行对应航段区分工况。
- **校验规则**：非负数字，最多两位小数。
- **状态逻辑**：沿用原港口维护条件，本故事不改行编辑交互。
- **异常场景**：负数、非数字或超过两位小数 / 不接受非法值 / 阻断非法值录入 /无。

**数据流与依赖：**

- **上下游模块/系统**：四项分项供 US-VTC-003 计算。
- **第三方对接**：无新增。
- **定时任务**：无新增。
- **数据同步**：无新增跨系统同步。
- **公用数据/表**：当前航次任务变更单据及其港口明细。
- **连带影响**：无新增待办、通知或状态流转。
- **权限与数据范围**：市场营销人员、调度人员和项目管理人员沿用系统统一权限，仅可查看已授权单据；有维护权限时方可修改对应指标。

**前置条件：** 当前单据存在可维护的港口记录。

**后置条件：** 四项分项天数可用于本行及总数行计算。

**关联 US：** 下游 US-VTC-003；关联功能 F-VTC-002。

**UI 原型：** 航次任务变更-原型-v1.0.html

### US-VTC-003：自动汇总港口航行天数

**作为** 已获航次任务变更查看权限的市场营销人员、调度人员或项目管理人员

**我想要** 看到系统自动计算的航行天数及总数

**以便于** 核对各工况分项与航段总天数的一致性，掌握方案的整体航行时间，减少人工加总差错

**验收标准：**

- [ ] 同一行四项为 1.25、0.50、空白、0.10 时，航行天数实时显示 1.85，且不可手改。
- [ ] 另一行航行天数为 2.15 时，两行的航行天数总数为 4；四项分项的总数也分别按列求和。
- [ ] 一行四项均未填时，该行航行天数按 0 计算；非法分项值不纳入计算。

**业务规则：**

- **操作规则**：有效分项变化后，实时刷新该行航行天数和总数行。
- **数据规则**：航行天数（系统计算）＝正常航行-ECA外天数＋正常航行-ECA内天数＋漂航-ECA外天数＋漂航-ECA内天数。总数行（系统计算）按各列求和，均以天计。
- **校验规则**：分项未填按 0；结果最多两位小数，不包含等泊和作业天数。
- **状态逻辑**：航行天数和总数行只读。
- **异常场景**：分项输入不合法 / 按分项校验处理，不以非法值重算 / 阻断非法值参与计算 / 无。

**数据流与依赖：**

- **上下游模块/系统**：读取 US-VTC-002 的有效分项，输出本行及总数行结果。
- **第三方对接**：无新增。
- **定时任务**：无新增。
- **数据同步**：无新增跨系统同步。
- **公用数据/表**：当前航次任务变更单据及其港口明细。
- **连带影响**：无新增待办、通知或状态流转。
- **权限与数据范围**：市场营销人员、调度人员和项目管理人员沿用系统统一权限，仅可查看已授权单据；有维护权限时方可修改对应指标。

**前置条件：** 存在港口行及对应分项字段。

**后置条件：** 系统展示最新行航行天数及五项列总数。

**关联 US：** 上游 US-VTC-002；关联功能 F-VTC-003。

**UI 原型：** 航次任务变更-原型-v1.0.html
